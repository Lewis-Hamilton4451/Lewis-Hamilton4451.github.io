# **服务器端漏洞---基础（<https://portswigger.net/web-security>）**

## **一.路径遍历（目录遍历）**

允许攻击者读取运行着应用程序的服务器上的任意文件，文件中可能包含：

- Application **code** and **data**
- **Credentials** for back-end systems - 认证信息
- Sensitive system operating **files**

在文件路径中，../../../序列表示**当前目录上一级目录的文件或文件夹**，可以用来找到指定文件(etc/passwd).

## 二.访问控制

访问控制是指对哪些人或哪些行为被允许执行某些操作或访问某些资源进行约束。在 Web 应用程序中，访问控制依赖于身份验证和会话管理（session）

- Authentication - 身份验证旨在确认用户确实就是他们声称的那个人
- Session management - 会话管理能够确定是同一个用户再次发起了多少个 HTTP 请求
- Access control - 访问控制决定了用户是否被允许执行他们试图进行的操作

1. **Vertical privilege escalation（垂直权限提升）**
   某个用户能访问到他访问不到的内容，就是垂直权限提升行为。例如一个普通员工能够访问管理员页面，并进行管理员操作。
   垂直权限提升现象发生在网页没有对敏感内容实施任何保护的情况下
   例如一个网站的/admin页面允许任何用户访问，而不只是知道这个链接的管理员
   特定的管理员URL可能被泄露在**robots.txt文件中和JavaScript代码里**，且能被任何用户访问
   即使特定的URL没有任何公开的信息，攻击者也可以通过词表暴力破解的方式找到敏感功能的位置
   - 基于参数的访问控制方法
     有的网页会通过特定的参数来确定你的访问权限和角色，这些参数包括：
     （这意味着可以通过改变这些参数的值来实现垂直权限提升）
     - 隐藏的字段
     - Cookie
     - 预先设定好的字符串参数
2. **Horizontal privilege escalation（水平权限提升）**
   某个用户能够访问属于其他用户的内容而不是自己的内容时，就是水平权限提升现象。例如一名员工能够访问其他员工的内容时，就是水平权限提升行为。
   在网站中，通过特定的参数匹配特定的值，就有可能发生水平权限提升现象，获取相关的数据和功能
   参数和值有可能从其他地方被泄露
3. **从水平权限提升到垂直权限提升**
   通过水平权限提升有可能可以获取到管理员账户的相关信息（账号，密码，特定网页URL），从而实现垂直权限提升

 

## **三.身份认证**

### 认证与授权：认证是指验证用户身份的过程，而授权则涉及用户是否被允许进行某些操作

- **暴力攻击**
  指攻击者通过不断尝试不同的用户名与密码组合来猜测有效的登录凭证
  攻击者可通过基本逻辑和公开信息来精确调整攻击的方式来提高攻击效率
- 强制用户选择用户名
  如果用户名有一定的规律，那对密码进行攻击就变得更加容易
  在审计过程中，需要检查网站是否公开了用户名称
- 强制使用高熵值的密码
  高熵值的密码会加大对密码进行暴力攻击的难度
  当用户经常使用的密码不符合一些网站的强制规定时，他们可能会仅仅进行一些小修改
  另外有的网站会强制用户在一段时间修改密码，用户也可能只会进行细微的修改
- 用户名枚举
  用户名枚举是指攻击者可以通过观察网页的变化来确定用户名是否有效，从而提高攻击效率
  通常发生在登录界面或者注册界面，例如当登录时显示密码错误或注册时显示用户名已被占用
- 绕过双因素验证
  双因素验证是指当用户输入完正确的密码后要继续输入验证码才能完成登录，这时候有可能在输入完密码后就已经是“已登录“状态了，有的网站在加载用户界面时不会判断是否完成了第二次验证

## **四.服务器端伪造请求（SSRF---Server-side request forgery)**

服务器端伪造请求允许攻击者使服务器端应用程序向非预期的目标位置发送请求，攻击者可能会促使服务器连接到组织内部的基础设施中的仅限内部访问的服务

- **针对服务器的SSRF攻击**
  攻击者会促使应用程序通过回环网络接口向服务器发送 HTTP 请求，如 `127.0.0.1` （一个指向回环适配器的保留 IP 地址），或者 `localhost` （该适配器常用的名称）
  必须通过回环网络接口的原因是一般管理员功能或者其他敏感功能只允许通过身份验证的用户操作，使用回环网络接口可以绕过身份验证
  关于为什么服务器会隐式信任来自本地机器的请求
  - 访问控制检查可能由位于应用服务器之前的另一个组件来执行，当与服务器建立连接时，该检查会被跳过
  - 为了应对灾难恢复情况，该应用程序可能允许从本地机器上的任何用户无需登录即可获得管理权限
  - 管理接口可能通过不同的端口号与主应用程序进行通信，用户可能无法直接访问该接口
    这种特性使得SSRF成为一种潜在的严重漏洞
- 针对其他后端服务器的SSRF攻击
  在某些情况下，应用服务器能够与那些用户无法直接访问的后端系统进行交互，这些系统通常拥有不能直接连接的IP地址

<br />

## **五.文件上传漏洞**

文件上传漏洞是指 Web 服务器允许用户将其文件上传到系统文件目录时，如果未能有效实施相应的限制措施，那么简单的图像上传功能也可能被利用来上传任意类型且可能具有危险性的文件，通常目的是触发服务器执行该文件

- **利用无限制的文件上传功能来部署网络外壳程序（Web Shell)**

  Web Shell 是一种恶意脚本，它允许攻击者通过向正确的端点发送 HTTP 请求，从而在远程 Web 服务器上执行任意命令

  例如以下php代码第一行可以获取指定文件的内容，第二行允许你通过查询参数传递任意系统命令
  ```PHP
  <?php echo file_get_contents('/path/to/target/file'); ?>
  <?php echo system($_GET['command']); ?>
  ```

* 利用文件验证漏洞来部署Web Shell

  提交HTML表单时，浏览器通常以POST请求的形式发送数据，并以`application/x-www-form-urlencoded` 的内容类型，但这种类型不适合发送大量的二进制数据，像PDF或是图像，所以通常使用内容类型为： `multipart/form-data`

  提交一个表单，用于上传图片，描述图片信息以及输入用户名。这时消息体会被拆分为多个部分，分别对应表单的各个部分，每个部分都有`Content-Disposition` 头部信息，还可能包含`Content-Type` 信息，浏览器会通过`Content-Type` 来判断上传的文件是否符合要求，但可以通过Burp Repeate来修改`Content-Type` 信息来绕过这个判断

## **六.操作系统命令注入（shell注入）**

| Purpose of command    | Linus       | Windows      |
| :-------------------- | :---------- | :----------- |
| Name of current user  | whoami      | whoami       |
| Operating system      | uname -a    | ver          |
| Network configuration | ifconfig    | ipconfig/all |
| Network connections   | netstat -an | netstat -an  |
| Running processes     | ps -ef      | tasklist     |

操作系统命令注入允许攻击者执行运行应用程序的服务器上的操作系统命令，通常会完全控制该应用程序及其数据

例如一个购物网站允许用户查看库存信息，这一功能是通过调用一个shell命令来实现的

依据这一特性，攻击者可以在命令后面用命令隔离符加上"echo hello"来测试是否存在shell注入漏洞

## **七.SQL注入**

SQL 注入是一种网络安全漏洞，攻击者可以通过这种漏洞干扰应用程序向数据库发送的查询，这样一来攻击者有可能能获得到一些敏感信息，另外，攻击者还可能修改数据让程序的数据和行为改变，甚至通过将 SQL 注入攻击升级破坏底层服务器或其他后端基础设施

可以执行以下操作来检测SQL注入

- 使用单引号字符 `'` 来查找错误或其他异常情况
- 一些与 SQL 相关的特殊语法，这些语法会计算出入口点的基础值以及另一个不同的值，然后寻找应用程序响应中的系统性的差异
- 布尔条件，例如 `OR 1=1` 和 `OR 1=2` ，可以找出应用程序响应中的差异
- 负载在作为 SQL 查询的一部分执行时，会触发时间延迟，然后检测响应时间上的差异
- OAST 负载旨在在 SQL 查询中执行时触发网络中的外部交互，并监控由此产生的所有交互情况

一个SQL请求如下：

```SQL
SELECT * FROM products WHERE category = 'Gifts' AND released = 1
```

<br />

- 所有详细信息（ `*` ）
- 来自(FROM) `products` 表格
- 在 `category` 的位置是 `Gifts`
- `released` 等于 `1` ，released是这个数据库中预定义的标识符，用于隐藏未发布的产品信息

在SQL中，” -- “是注释符

一个修改后的SQL请求：

```SQL
SELECT * FROM products WHERE category = 'Gifts' OR 1=1--' AND released = 1
```

这个请求会返回所有满足以下条件的项目：要么 `category` 等于 `Gifts` ，要么 `1` 等于 `1` 。由于 `1=1` 始终为真，因此该查询会返回所有项目

```
Warning：在将条件语句注入 SQL 查询时需要注意安全。即使该条件在你所插入的上下文中看起来并无危害，但实际上应用程序常常会在多个不同的查询中使用来自同一请求的数据。例如，如果条件语句超出了 UPDATE 或 DELETE 这样的语句范围，就可能会导致数据意外丢失
```

***

SQL注入漏洞可以**破坏应用程序的逻辑结构**

下面这个请求

```SQL
SELECT * FROM users WHERE username = 'wiener' AND password = 'bluecheese'
```

这是一个登录请求，这种情况下，攻击者可以把对密码的检查注释掉，从而使用任意已注册的用户名登录

```SQL
SELECT * FROM users WHERE username = 'administrator'--' AND password = ''
```
